# Landscape watch — 2026-10-12

Scope: `gh` for the seven GitHub entries (window: since 2026-10-05), WebSearch
for Claude Code releases and discovery. All seven repos still exist at the
watchlist names; none moved or archived. WebSearch found no project clearly
launched in the last month — discovery was thin this week.

## Worth stealing

- **Confirm an approval landed before saying "allowed".** paseo's remote
  `permit allow` reported success while the Codex request was still pending
  (the SSH tunnel closed before the daemon acknowledged). Both allow and deny
  now wait for the daemon ack and fail after 15 s with a hint
  ([PR #6607](https://github.com/getpaseo/paseo/pull/6607)). Touches: ask cards
  and approvals relayed from the phone — show "sent" and "applied" as separate
  states (same idea as last week's read-receipt item, roadmap item 16).
- **Handlers registered while offline must survive the reconnect.** happy's
  offline session stub dropped message, abort and kill handlers when the real
  session replaced it, so Stop from the app was silently ignored
  ([PR #1858](https://github.com/slopus/happy/pull/1858)). Touches: the relay /
  phone-jobs worker — after any reconnect, re-attach interrupt and barge-in
  paths and test that Stop still works.
- **Make "connection lost" visible in chat.** claudecodeui now shows when the
  chat WebSocket is down, and is separately working on keeping the unsent
  message ([PR #1485](https://github.com/siteboon/claudecodeui/pull/1485),
  [#1407](https://github.com/siteboon/claudecodeui/pull/1407)). Touches: the
  Sasonica composer — a banner plus "message kept, will send" beats a silent
  drop on a locked or roaming phone.
- **A queued message must not fire while background work still runs.**
  claudecodeui fixed its "Queued · will send when this finishes" card
  releasing after a turn that left background tasks running
  ([PR #1434](https://github.com/siteboon/claudecodeui/pull/1434)). Touches:
  our queued-send and the Stop/idle speech hook, which has the same "done vs.
  still working" ambiguity noted last week.
- **Ask before first exposing the server to the internet.** opencode's
  `pair --remote` now explains the exposure (E2E encrypted, server password) and
  confirms before enabling a tunnel
  ([PR #54561](https://github.com/anomalyco/opencode/pull/54561)). Touches:
  pairing / `/targets` and any future hosted-relay opt-in — one explicit
  consent step, with the local alternative named.

## Suggested additions

- [QuivrHQ/247-claude-code-remote](https://github.com/QuivrHQ/247-claude-code-remote)
  — Tailscale-based phone/desktop access, Fly.io VM provisioning, PWA; useful
  as a contrast to our relay (no hosted relay, tailnet only). Last push
  Feb 2026, so older than "new".
- [praneybehl/claude-code-voice-hook](https://github.com/praneybehl/claude-code-voice-hook)
  — Stop hook that strips markdown and posts to any OpenAI-compatible
  `/v1/audio/speech` server; a minimal reference for the text-cleaning step
  (stale: last push Jan 2026).
- Rhyme CLI pattern ([write-up](https://openclawdatabase.com/news/videos/2026-08-31-rhyme-cli-agent-voice-replies/))
  — a CLI plus Stop hook for spoken replies, with the claim that prompt
  instructions get skipped while hooks don't; matches our hook-owned speech.
- [AgentsRoom](https://agentsroom.dev/claude-code-remote) — native mobile app
  with E2EE sync, terminal streaming and push notifications; closed-source as
  far as seen, worth a glance at how it frames notifications.
