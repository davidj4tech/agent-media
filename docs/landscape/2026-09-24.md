# Landscape watch — 2026-09-24

Scope note: GitHub only (`gh`), from release notes and repo search. Web and
Hacker News search were not used this run, and Anthropic's own changelog was
not checked, so the "Claude Code remote" entry below is a gap, not a finding.

## Worth stealing

- **Session recovery after the daemon forgets.** Happy 1.2.5 recovers
  resumable sessions when daemon state is lost, blocks two owners resuming the
  same session, and picks up transcripts that show up late or after a watcher
  restart. We hit the same class of problem (headless sessions with no pane,
  "closed is not archived"). Seen:
  [slopus/happy cli-1.2.5](https://github.com/slopus/happy/releases/tag/cli-1.2.5).
  Touches: session lifecycle / idle-close items in the roadmap.
- **Composer draft synced across devices, plus message acceptance and queue
  metadata.** Same Happy release: a draft typed on the phone is visible at the
  desk, and the client learns whether a message was accepted or queued. Touches:
  the reply box and stop/queue semantics in the server contract.
- **A phone mode that ends every turn with tappable options and one push line.**
  `claude-code-mobile-mode` is a plugin: per-session switch, questions go out as
  `AskUserQuestion` chips, one result-first line as the notification, answer
  first with no preamble. It is close to what our ask cards and the "replies are
  short" rule already do; worth comparing the per-session switch, which we lack.
  Seen: [holystreetballer/claude-code-mobile-mode](https://github.com/holystreetballer/claude-code-mobile-mode)
  (the repo name in search results, hnkabraham/..., now redirects there).
  Touches: ask cards, notifications.
- **Configurable event webhooks.** Omnara's daemon added them in omnarad 0.1.27,
  so a session's events (asks, finishes) can reach anything, not only the app.
  Seen: [omnara-ai/omnara PR 556](https://github.com/omnara-ai/omnara/pull/556).
  Touches: notifications, and the outbound tunnel work.
- **Cancel must unwind one request, not the server.** VoiceMode 8.12.0 fixed
  ESC during a voice call wedging the next `converse()` and then killing the
  MCP server; the fix is handling `CancelledError` at the boundary the MCP SDK
  expects. Worth a check against our barge-in and stop path for the same trap.
  Seen: [mbailey/voicemode v8.12.0](https://github.com/mbailey/voicemode/releases/tag/v8.12.0).
  Touches: stop = "the one thing happening", barge-in.

## Per project

**slopus/happy** — Active (v1.2.5 on 2026-09-22, betas the week before). Beyond
the items above: Codex turn timeout removed, plugin directories forwarded to
Claude, macOS dark-wake reconnect avoided. Realtime voice and E2E encryption
remain the headline features.

**siteboon/claudecodeui (CloudCLI)** — v1.37.3 on 2026-09-08, repo pushed as
recently as yesterday. Now covers Claude Code, OpenCode, Cursor CLI and Codex.
Notable: arrow-key recall of sent messages in the composer, a unified provider
workflow with faster transcript rendering, a "Conversations" sidebar row drawn
like a Projects row, and a fix where an option label containing ", " was split
into two answers (a bug our multi-select ask cards could share; worth a test).

**anomalyco/opencode** — Moved: `sst/opencode` now resolves to
`anomalyco/opencode`; update the watchlist. v1.18.32 (2026-09-21) is provider
bugfixes and model additions only. Nothing on the remote or web client in the
recent releases I read.

**omnara-ai/omnara** — Repositioned as "the open-source alternative to Claude
Managed Agents"; releases are a daemon (`omnarad`) and a `cluster` component,
several per week. Event webhooks and saved compiled configs are the recent
features. Less phone-first than before.

**amantus-ai/vibetunnel** — Quiet: last push 2026-08-05, last release
1.0.0-beta.18 on 2026-07-11. Nothing notable.

**mbailey/voicemode** — v8.12.0 (2026-07-21), pushed 2026-09-21. The ESC/cancel
fix above is the only item relevant to us.

**Claude Code on web / mobile / remote control** — Not checked this run. Search
shows a small ecosystem growing around Remote Control (keep-alive supervisors,
tmux launchers, a menu-bar manager, a tunnel-recovery skill after account
switches), which suggests its session tunnel is fragile in practice.

**TTS-hook projects** — See suggestions; nothing that beats our ordering and
barge-in handling.

## Suggested additions

- [holystreetballer/claude-code-mobile-mode](https://github.com/holystreetballer/claude-code-mobile-mode) —
  phone-driven turns end with tappable options and one push line.
- [giladreich/claude-code-tts](https://github.com/giladreich/claude-code-tts) —
  announces the agent's actions ("Editing extension.ts") as well as replies;
  compare with our step list and Bash descriptions.
- [YeyingShi221/diting](https://github.com/YeyingShi221/diting) — voice overlay
  with off / active (TTS) / duplex (TTS + STT) modes; a simple mode model to
  compare with ours.
- [SevFle/pi-voices](https://github.com/SevFle/pi-voices) — selectable output
  voice styles applied to every turn, for the pi agent.
- [devsecopsinc/claude-remote-control](https://github.com/devsecopsinc/claude-remote-control) —
  one Remote Control server per workspace in tmux, surviving reboot; the same
  problem as our headless-session plumbing.
- [timylya777/opencode-mobile](https://github.com/timylya777/opencode-mobile) —
  Expo/RN Android client for opencode; tiny, but the first opencode phone
  client found (relevant to the opencode proposal in docs/proposals).
