# Handover — documents you can listen to, and the day the speech path stopped lying

Status: **current**
Date: 2026-08-10

Supersedes [2026-08-09](2026-08-09.md), which covered the speech-display
refactor. Everything in it is done.

---

## Start here

Speech works, documents can be listened to, and the phone lane no longer runs
over ssh. Two things are unfinished, both named at the bottom.

The through-line of the whole day: **every failure was silent.** Not one
announced itself. A renamed script, a dead hostname, a stale environment
variable, a breaker skipping the call that *was* the playback — each produced
audio that simply didn't happen, with every layer above reporting success. Most
of the commits below are less about the bug than about making that class of
failure impossible to have again.

## What changed

### Speech was dead for an hour and nothing noticed

dotfiles `e1b9a9f` renamed the phone's renderer to `say.sh`, said so in its
commit message, and left the command pointing at `say-sonia.sh` — which that
same rename deleted. Every reply from 02:04 ssh'd to a path that did not exist.
`remote-say` never checked the exit status, so each one was written to history
as though spoken.

Fixed in `c91e9aa`: a non-zero exit goes to the error log and the history row
carries `failed`. It earned its keep the same day, catching an unrelated
outage within minutes.

### Documents

`media doc list|play|text|agenda`, and `d` in the popup. Playback goes to the
**book channel**, not speech, because that channel already has chapters, a
resume position and bookmarks — the exact set a ten-minute document needs.
Headings become mpv chapter marks, so the popup's chapter browser navigates by
section.

The projection is the part that decides whether any of this is bearable: code
fences and tables are **announced, not read**. Org support followed
(`e034d33`) — drawers, `#+keyword:` lines and heading tags are invisible to a
reader, so they are invisible to a listener; `#+begin_quote` *is* read, because
it is prose. `MEDIA_DOC_ROOTS` now includes `~/org`, and selection is by tag
rather than folder, since PARA membership is a filetag and a note belongs to
several places at once.

Context (`49b721e`): the enclosing git repo is added as a root, and the tmux
session promotes matching notes. Neither ever *removes* a row — context that
narrows silently cannot be told from context that filters.

### The Emacs side, and why the picker should stop growing

`am-read.el` binds `media doc play` where selection already happens — dired,
the current buffer, `org-roam-node-read` — plus `media doc play --stdin` for a
region or a buffer. agent-media's own picker duplicates consult, telescope and
projectile, badly. **The picker stays for the phone, where there is no Emacs,
and stops being where effort goes.**

Driving it from the real daemon found three bugs that had nothing to do with
Emacs and everything to do with being called from a process that did not start
in a login shell: a missing `edge-tts` escaping as a traceback instead of the
documented fallback, a bare `media` a systemd daemon cannot find, and
`SinkBook.play`'s loadfile not being `critical` (`fab3b2c`).

### Seventeen seconds of coordination for three seconds of words

A 3s utterance took 25.2s. Measured: render 1.3s, Python on the device 0.25s,
audio ~3s — and **22.6s of coordination**. Streaming synthesis, the obvious
fix, would have saved part of 1.3s.

- `route/_android` pinned its own ControlPath, minting a second ssh master
  beside the ambient one. Its 300s persist went cold between bursts while the
  600s one stayed warm, so the pause routinely paid an ~11s cold connect.
- That 11s tripped the android breaker, whose "slow" mark was 900ms against a
  link whose honest warm round trip is 0.9s. The pause alternated between
  costing eleven seconds and silently not happening.
- The remote-say path never called `pre_pause_remote()`, which exists precisely
  so that ssh overlaps the render.
- `book.active()` and the music now-playing read were sequential, though they
  ask unrelated questions of unrelated players (`e431f93`).

`before_speech` 16.9s → 4.1s, `after_speech` 5.7s → 0.9s.

### Transport moved to HTTP

`rsync` over ssh needs a reachable host, a resolvable alias, a writable remote
cache and a probe that finishes inside its timeout — all four failed at least
once today, each as silence. The clip server's root moved up one level so it
serves `docs/` beside `audio/`, and `SinkBook.play` hands mpv a URL
(`ad86acd`). A rendered document to the phone: **23.7s → 4.7s**.

Then the say path itself (`deploy/phone/say-http.py`, a runit service on
:8790). It shells out to `say.sh` rather than reimplementing it — two copies of
the render path is what caused the morning's outage.

## Three traps worth knowing before debugging anything here

**A long-lived process pins stale config.** The tmux server had been up since
6 Aug, before the tailnet rename, and the env loader only fills *unset* vars —
so `MEDIA_SPEECH_CLIP_SSH_PHONE=p8ar` (a name that no longer resolves) was
pinned into every pane, popup and hook. Starting a new *session* does not help;
the server is the same process. `tmux show-environment -g | grep MEDIA_` before
suspecting the code. The same shape appeared three more times: an ssh
ControlMaster keeps the keepalives it was born with, a speech-dispatcher daemon
with `-t 0` never re-reads its config, and a running bash script re-reads
itself from a byte offset.

**Editing a running bash script corrupts it.** bash reads lazily from an offset
in the open file, so inserting lines into `media-popup` while it ran left a
popup that could not be quit and cost a tmux session. Each popup script is now
one brace group with `exit` **inside** it — both halves required, and the
second is easy to get wrong (`e095494`).

**A bound tuned on a fast network is a fault injector on a slow one.** This
link is 450ms RTT with ~20% loss. A 900ms "slow" threshold, a 12s probe
timeout, a 60s render timeout and a 45s breaker window were each calibrated for
a LAN and each broke something here.

## The outliers

A 2s clip that normally takes 6s took 104.5s, and 104.5 = 90 + the work.
`ServerAliveInterval 30 × ServerAliveCountMax 3` is ninety seconds before ssh
gives up on a stalled connection.

**With multiplexing the keepalives that matter belong to the master.** Options
passed by a client joining an existing master are inert — so the
`-o ServerAliveInterval=5` that `media-lane` carefully passed had never once
applied. Fixed in dotfiles `1481f2f` as a per-host block; a master keeps
whatever it was born with, so `ssh -O exit p8a` is required for it to take.

## Unfinished

**The speech-dispatcher output module does not load.** `am_speechd_module.py`
speaks the protocol correctly standalone — INIT, LIST VOICES, SET, SPEAK,
CHAR declined, QUIT all verified by driving it on stdin — and speaking through
it reaches the phone. But `spd-say -O` lists no modules at all.

Ruled out: the `AddModule "am"` line is present and uncommented in
`/etc/speech-dispatcher/speechd.conf`; `/etc/speech-dispatcher/modules/am.conf`
exists; the binary is symlinked into `/usr/lib/speech-dispatcher-modules/` and
is executable; there is no user-level `~/.config/speech-dispatcher` overriding
`/etc`; and killing the daemon gets a fresh pid that still loads nothing.

Not yet tried: raising `LogLevel` past 3 and finding where the daemon actually
logs (`LogDir "default"` produced no file, and there is no journal entry), or
running the module the way speechd runs it — `<binary> <config-dir>` — to see
whether it is being dropped at handshake. That is where the next hour should
go.

**Also open**

- Speech clip *prefetch* uses the same ssh path the book channel just left. It
  works, but it is the last transport that can fail silently.
- `pause_for_speech` is still a synchronous round trip inside `before_speech`.
- The 55s and 190s outliers were seen but not reproduced since the keepalive
  fix; the arithmetic is the evidence, not a reproduction.
